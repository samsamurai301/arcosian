# Arcosian (core plugin)

The core of the Arcosian suite: a principal game developer persona, a game-dev codex, a shared ontology, 24 agents, 9 workflows, simulators and solvers, an asset and audio gateway, mobile project templates and enforcement hooks. Targets mobile games on Godot 4 and Unity 6; other engines are covered at the advice level by `engine-alternatives`.

Install: `/plugin marketplace add <path or repo>` then `/plugin install arcosian@arcosian`. Deeper docs are in `docs/`.

## How you use it

Everything is a skill; user-facing ones are slash commands of the form `/arcosian:<name>`. Start with `/arcosian:studio`, which detects project state and routes you. Workflows also run as `/arcosian:<workflow-name>`.

## Commands (process skills)

| Command | Purpose | Runs workflow |
|---|---|---|
| `studio` | Entry point; detects state, explains the pipeline, picks the next step | none |
| `new-game` | Brief, market scan, concept tournament, contract, feature plan, `gs.py init` | concept-tournament, market-scan |
| `concept-lab` | Ideation methods, concept cards, scoring rubric | concept-tournament |
| `design-review` | Multi-discipline review of the contract | design-review |
| `market-scan` | Competitive and market research with sourced report | market-scan |
| `deconstruct` | Deconstruct a game into the ontology | deconstruct-game |
| `build-feature` | One feature through the five gates | build-feature |
| `playtest` | Deterministic playthroughs, bots, persona playtests, visual QA | playtest-sweep |
| `balance` | Economy and difficulty tuning with simulators | balance-pass |
| `optimize` | Mobile performance pass against budgets | none |
| `asset-production` | Visual assets via the gateway with style lock | asset-batch |
| `audio-production` | Music, SFX, voice with loop and loudness QC | none |
| `ship` | Compliance pre-flight, signed builds, metadata, internal tracks; never submits for review | release-candidate |
| `operate` | Post-launch analytics, live-ops calendar, A/B tests, remote config, crash triage | none |
| `postmortem` | Structured postmortem and knowledge capture | none |

## Workflows

| Workflow | What it does |
|---|---|
| `concept-tournament` | n concept cards from distinct angles, 3 judges, pairwise finals, refutation, synthesis |
| `deconstruct-game` | 7 parallel lenses, merged into a deconstruction document, then fact-checked |
| `design-review` | Lens reviewers, 2 skeptics per finding, report with proposed edits (not applied) |
| `market-scan` | Research fan-out with a web budget per agent, cross-check, sourced report |
| `build-feature` | Build, run five gates, critic refutes, up to 3 fix rounds |
| `asset-batch` | Per-asset pipeline: prompt, generate, post-process, import, critique, manifest |
| `playtest-sweep` | Playthroughs, bots and personas, deduped and verified findings |
| `balance-pass` | Model, simulate, propose, re-simulate, report |
| `release-candidate` | Pre-flight, bump, builds, perf, metadata, review; internal track only |

## Tools

Python scripts (stdlib only) in `scripts/`:

| Script | Use |
|---|---|
| `gs.py` | Project-state CLI: `init`, `status`, `summary`, `validate`, `feature` (list, add, next, show, start, gate, pass, block), `evidence-dir`, `progress`, `budget`, `kb`; `--selftest` |
| `gslib.py` | Shared library for the CLI, hooks and tests |
| `validate_json.py` | Schema validation against `scripts/schemas/` |
| `economy_sim.py`, `progression_calc.py`, `gacha_calc.py` | Economy, progression curves, gacha odds and pity |
| `difficulty_curve.py`, `match3_sim.py`, `puzzle_solver.py`, `pcg.py` | Difficulty, match-3 simulation, solvers, procedural generation |
| `ab_test.py`, `retention_ltv.py`, `event_taxonomy.py` | Experiment analysis, retention and LTV, telemetry taxonomy |
| `compliance_preflight.py`, `store_metadata.py`, `perf_budget.py` | Store policy checks, listing metadata, perf budgets |
| `audio_post.py`, `image_post.py` | Loudness and loop QC; image post-processing |
| `audit_plugin.py` | Structure audit and `--map` knowledge-map generator |

Run any script with `--help`; most support `--selftest` or a documented demo mode.

**Gateway.** `mcp/studio-gateway` (zero-dependency Node) exposes 14 tools: `gs_status` (call it first), `image_generate`, `image_edit`, `image_postprocess`, `model3d_generate`, `model3d_status`, `audio_music`, `audio_sfx`, `audio_voice`, `manifest_query`, `manifest_update`, `licence_check`, `budget_status` and `kb_search`; its README documents each. Providers: Gemini (Lyria music uses the same key), OpenAI, Recraft, fal, Tripo, Meshy, ElevenLabs, Stability. With no key, `GS_MOCK=1` or `dry_run` it writes valid placeholders at cost 0.

**Project state.** `gs.py init` creates `.gamestudio/` in the game project: `config.json`, `contract.json`, `features.json`, `progress.md`, `budget.json`, `assets/manifest.json`, and the directories `design/`, `art/`, `audio/`, `concepts/`, `research/`, `economy/`, `levels/`, `analytics/`, `evidence/<FEATURE-ID>/`, `playtests/`, `reports/` and `snapshots/`. The full table with contents and schemas is in `docs/ARCHITECTURE.md` section 2.

**Templates.** `templates/godot-mobile`, `templates/unity-mobile`, `templates/ci` (GitHub Actions, fastlane, Codemagic), `templates/docs` (GDD one-pager, style bible, audio bible, playtest plan, soft-launch plan, postmortem, pitch outline, risk register, store listing, live-ops calendar, and more).

**Hooks.** SessionStart (project summary), PreToolUse (release and secret guards, feature-list gate check), PostToolUse (edited-file check), Stop and SubagentStop (done features must pass gates), TaskCompleted, PreCompact (state snapshot). See `docs/ARCHITECTURE.md`.

**Evals.** Eight cases live in the repository's `evals/arcosian/`, outside the plugin folder so installs stay small; run instructions in `evals/arcosian/README.md`.

## What this plugin runs, sends and fetches

- **Runs:** hooks at session start, before shell and file tools, after edits, at stop and before compaction (`node hooks/scripts/run-python.mjs` starts each Python handler); the Python tools in `scripts/` when Claude runs them; the `studio-gateway` MCP server (`node mcp/studio-gateway/server.mjs`).
- **Sends:** the gateway calls a generation provider only after you add its key and ask for an asset, within the project's budget cap: Google (Gemini image models, Lyria, TTS), OpenAI, Recraft, fal, Tripo, Meshy, ElevenLabs, Stability AI. Without keys it writes placeholders and makes no network calls.
- **Fetches:** the generated files, from the provider that made them.
- **Writes:** project state and generated assets inside your project (`.gamestudio/` and your asset folders), and the chosen Python command in the plugin data folder.
- **Never:** no telemetry, nothing sent to the authors, no store submission without you. Details per destination: `PRIVACY.md` at the repository root.

## Configuration

Set in the plugin's user configuration (all optional, sensitive values are stored as such): `gemini_api_key`, `openai_api_key`, `recraft_api_key`, `fal_key`, `tripo_api_key`, `meshy_api_key`, `elevenlabs_api_key`, `stability_api_key`, and `asset_budget_usd` (default 50). A project's `.gamestudio/config.json` overrides the budget.

## Adapters

`arcosian-godot`, `arcosian-unity`, `arcosian-blender`, `arcosian-vendors`, `arcosian-commerce`. Each depends on this plugin and adds MCP bridges plus one skill that says when to use them. The Godot and Unity adapters also give Claude Code a language server for their language: Godot's own GDScript server, and csharp-ls set up for Unity projects (errors after each edit, go to definition, references, symbols).
